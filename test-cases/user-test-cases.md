Unit-тесты

RegisterUserUseCase

1. Успешная регистрация — валидный email/password/name → создаётся User, пароль захеширован, возвращается User
2. Дубликат email — email уже существует → выбрасывается ошибка (например, EmailAlreadyExistsException)
3. Пароль хешируется — проверить что PasswordEncoder.encode() вызывается, и в User попадает хеш, а не plain text

AuthenticateUserUseCase

4. Успешный логин — верный email + пароль → возвращается JWT токен
5. Неверный пароль — правильный email, неправильный пароль → ошибка аутентификации
6. Несуществующий email — email не найден → ошибка аутентификации (та же, что и для неверного пароля — чтобы не раскрывать наличие аккаунта)

JwtTokenProvider

7. Генерация токена — по UserId/email генерируется валидный JWT
8. Парсинг токена — из валидного токена извлекается userId/email
9. Просроченный токен — expired JWT → ошибка валидации
10. Невалидный токен — повреждённый/чужой JWT → ошибка валидации

Integration-тесты

POST /auth/register

11. 201 — валидный запрос → пользователь создан, в ответе id + email + name (без пароля)
12. 409/400 — повторная регистрация с тем же email → ошибка
13. 400 — невалидный email / пустой пароль / пустое имя → validation error

POST /auth/login

14. 200 — верные credentials → в ответе JWT токен
15. 401 — неверный пароль → Unauthorized
16. 401 — несуществующий email → Unauthorized

Защищённые эндпоинты

17. 401 — запрос без токена к защищённому эндпоинту → Unauthorized
18. 401 — запрос с невалидным/просроченным токеном → Unauthorized
19. 200 — запрос с валидным JWT → доступ разрешён

Полный flow (e2e)

20. Register → Login → Access protected endpoint — регистрация, логин, использование полученного токена для доступа к API
